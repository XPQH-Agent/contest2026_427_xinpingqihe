## 1. 开机即用（新增）

- GUI 由 `board_late_initialize()` 在系统起来后直接拉起（Kconfig 门控），冷启动不再停在 NSH。
- 开屏动画改为位图分层合成（openvela ∞ 光带背景 + 双标识并排），**1.4 s** 完成；位图全部 `const` 放 flash，**SRAM 增量为 0**。
- 修掉与自启冲突的应用内截图路径：改为向已在跑的 GUI 投递请求，不再起第二个 LVGL 实例。

## 2. 电源与电池（新增）

- 充电检测读错设备：实际 `VBUS_DET` 是 **PA_44**（此前读 PB_34 恒 0，导致"插着电显示没充电"）。
- 用满电 4.24 V 实测反标定分压系数 **1.267**（`PW_VBAT_DIV_NUM=1267/1000`），替换原凭物理推算的 2.01。
- 电量显示四舍五入 + 变化才重绘，消除 99/100 抖动与每秒整屏重画。
- 新增产线化命令：`phywear batcal <mV>`（现场反标定）、`phywear plog`（掉电即失的环形日志）。

## 3. 显示与性能（改进，口径分三层）

- 「画面撕裂」根因定位到 SiFli LCD 驱动：双 framebuffer 下 `render_start()` 把整屏标脏，而该驱动双缓冲是"两块轮流当扫描源 + 等扫描线"，不是 vblank 翻页；因此任何只画脏区的改法都会被撕开。
- 结论是**用整屏重绘换不撕裂**（33.5 ms/帧、**30 fps**），保留开关 `PW_LCD_FULL_INVALIDATE`。
- 三个帧率口径分开写清：**官方 benchmark 39 FPS** / **本队页面级 48–49 FPS** / **整屏重绘 30 fps**；面板 VFR 60 Hz 是物理上限（CO5300AF-01 手册，命令表无帧率控制寄存器）。
- 新增 `fpsbench` / `lcdbench` / `phywear fps` / `phywear px` 四个诊断入口，现场可自证。

## 4. 蓝牙（重大新增，含一处未闭合）

### 4.1 已交付

- 查出 SiFli `sf32lb52_bth4.c` 的 HCI emulate 表把 **14 条命令**（`SET_EVENT_MASK`、`WRITE_SCAN_ENABLE`、`WRITE_CLASS_OF_DEVICE`、`WRITE_SSP_MODE` 等）直接吞掉并假成功，导致主机以为配好了、手机却搜不到；逐条直发探针验证控制器确实支持后放行，**BR/EDR 现在真可被发现/可连接**（提交 `b72141a`、串口实测 `cmd 0x0c1a` 两次 `cc status=0x00`）。
- 自研 **BNEP/PAN 帧层**（`app/phywear/pw_bnep_frame.c`）：SETUP / FILTER / 数据帧编解码，主机侧 **41 项单测全绿**。
- **MIoT 米家广播**（`pw_mibeacon.c`）：按小米《MI Beacon v.29》逐字节实现 AD `0xFE95`，**19 项单测全绿**，冒烟帧与官方举例逐字节一致。进米家 App 需企业资质，**未接入**，见 `docs/21` 准入清单。
- **BLE GATT 文本通道**（`pw_btgatt.c`）：服务 `e0f1a000-1b2c-4d5e-8f90-a1b2c3d4e5f6`，Text 特征 `e0f1a003-…` 写入后自动 `echo:` 回通知；桌面/手机侧回环测试 8/8 + 13/13 通过。**这条通路不需要配对、不依赖下述 PAN 卡点。**

### 4.2 PANU（手机网络共享客户端）工程化：六处修复合入

| # | 位置 | 问题 |
|---|---|---|
| 1 | `pw_bnep.c` | `pan_l2cap_recv()` 用 1600 B 栈数组，而 `BT_RX_STACK_SIZE=1200` → 必栈溢出（改 `static`） |
| 2 | `pw_bnep.c` | 回调里重复 `net_buf_unref()`（host 已在 `l2cap_br.c:2104-2105` 释放） |
| 3 | `pw_bnep.c` | `memset` 后未设 `rx.mtu`（=0），`l2cap_br.c:769` 因此不发 MTU 选项，反而宣告 MTU=0（设 1691） |
| 4 | `pw_bnep_frame.c` | Filter Net Type Set 少写 2 字节"列表长度"，手机判 bad length → `pan_fail` → DHCP 起不来 |
| 5 | `pw_bt.c` | `PW_BR_CONNECTABLE/DISCOVERABLE` 被写成 0/0（板上固件是 1/1），经典可见性根本没开 |
| 6 | `defconfig` | 补 `BT_MAX_CONN=2`（LE 与经典共用 `acl_conns[]`，=1 时经典连接被拒 `0x0D`）、`BT_BUF_ACL_RX_SIZE=1605`（原 1025 → L2CAP RX MTU 1021 装不下 1501）、`DHCPC_BOOTP_FLAGS=0x8000`（Android NAP 单播 OFFER 需要广播位） |

以上六项已合入 `dev-ai-contest-2026`（提交 `a05c8cf`）。
另有两处**平台驱动**修复（H4 帧必须一次整帧写进邮箱 ring、把新增 net_buf 池注册进 `_net_buf_pool_list[]`）位于 openvela 主树的 `vendor/sifli/` 与 `external/zblue/`，不在本仓库内。

### 4.3 当前卡点（如实）

控制器收下 SMP 的 STK（回 `cmd 0x201a`、`cc status=0x00`）后**从不发 `evt 0x08`（Encryption Change）**，主机等满 30 s 超时断开。因此 **PAN/BNEP 数据面尚未在真机打通**，本文与提交材料一律标"在研"，不作为演示前置。演示与产品叙事改用 4.1 的 BLE GATT 文本通道 + 端侧离线能力。

## 7. 已知限制（同步更新）

- PAN/BNEP 数据面：**在研**（4.3 的 `evt 0x08` 卡点）。
- `PPP over BLE` / `USB CDC-ACM + SLIP`：实验性通路，宿主侧需跑用户态 PPP 对端，不代表板子有独立互联网出口。
- 米家接入：协议层已实现，**未申请企业资质、未接入**。
- 整屏 30 fps 是拿"整屏重绘"换来的不撕裂；页面级 48–49 FPS 是分区刷新口径，两者不可混用。
