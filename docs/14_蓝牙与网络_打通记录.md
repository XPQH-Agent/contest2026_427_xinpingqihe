## 结案（2026-09-18）

本文件上面那些"未完成 / 无结论"的部分**已由 `docs/16_蓝牙B1根因与修复.md` 结案**：

- **B1 根因**：不是传输层配置，而是 **NuttX fd 表按 task_group** ⇒ H4 TX 跨组
  `write()` 恒 `EBADF(errno 9)`；`-EIO` 是伪造 status 0x1F 翻译出来的假象。
- **B1 / B2 已实测通过**；B3 需人工（`tools/pw_bt_b3.py` 一条命令判定）。
- **WiFi 硬件不可达**（本板无 WiFi 网卡，`ifconfig: open failed: 2`），
  但 **N1 / N2 已改走 PPP over BLE 达成**（2026-09-18 深夜，见下）。

### 追加结案：N1 / N2 用 PPP over BLE 打通（2026-09-18 深夜）

WiFi 与 USB-SLIP 两条路都断（无网卡 / 没数据线）之后，第三条路走通了：

* **设备侧**：`apps/examples/phywear/pw_btppp.c` —— 第二个 GATT 服务做 BLE↔pty 字节管道，
  pty 另一头是**真正的 NuttX pppd**；`phywear btppp &` 启动。
* **宿主侧**：`tools/phywear/pw_bt_ppp.py --peer` 自己当 PPP 对端（LCP+IPCP+ICMP，
  **不需要 root**）；帧编解码在 `tools/phywear/pw_ppp_frame.py`。
* **实测**：设备 `ifconfig` → `ppp0 … at RUNNING mtu 296 / inet addr:192.168.7.2 DRaddr:192.168.7.1`；
  `ping -c 3 192.168.7.1` → **3 sent / 3 received, 0% packet loss**。
  一键验收 `python3 tools/phywear/pw_bt_ppp_e2e.py --out <dir>` **6/6**。
* **卡点真相**：上一轮记的"SRAM 装不下"其实是 **NuttX hpwork/lpwork 栈各 16,096 B**
  （只是继承了板级 `DEFAULT_TASK_STACKSIZE`，NuttX 默认 2 KB）—— 显式改 8192 一次省 **15,808 B**。
* **证据**：`docs/evidence/bt-ppp-e2e-20260918/`（串口原文 + 宿主对端原文 + SHA256SUMS）、
  `docs/evidence/ws-stack-20260918/`（省 SRAM 那一步的安全性验证）。
* 详细根因与 7 个坑：`docs/16 §13.6e`、`docs/07` 坑 37–44。

本文件保留作**过程记录**（含当时的误判与教训），结论以 `docs/16` 为准。
